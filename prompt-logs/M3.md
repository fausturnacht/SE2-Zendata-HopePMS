## Entry 1
**Date:** April 28, 2026  
**Task:** Address Supabase warnings and verify if RLS is enabled
 
**Prompt given to AI:**  
I've already enabled RLS on the necessary tables, but Supabase Security Advisor still reports that RLS is disabled. How can I check if RLS is actually enabled on a table?
 
**What the AI produced:**  
Provided the SQL command to confirm RLS policies and explained that rowsecurity = true means RLS is enabled:
	SELECT schemaname, tablename, rowsecurity
    FROM pg_tables
    WHERE schemaname = 'public';
Suggested to also check active policies with: 
	SELECT * FROM pg_policies WHERE schemaname = 'public';


 
**What I changed / improved:**  
None.
 
**What I learned / decided:**  
Supabase warnings highlight every table in the public schema without RLS, not just the ones necessary for PMS. I can confirm RLS activation directly from `pg_tables` and `pg_policies`.

## Entry 3
**Date:** May 4, 2026  
**Task:** Fix bug where only the most recent stamp is retained instead of full history
 
**Prompt given to AI:**  
Product dropdown and database only retain the most recent stamp instead of full history. Expected behavior: maintain an audit trail of all stamps and display complete history. Actual behavior: overwrites previous stamps. How should I fix this?
 
**What the AI produced:**  
Identified root cause: `stamp` column (`VARCHAR(60)`) only stores a single value, overwriting older entries. Recommended creating separate audit log tables (`product_stamp_log`, `pricehist_stamp_log`) to store all changes. Suggested triggers on `product` and `priceHist` to append new rows to the log tables on every insert/update. Provided SQL scripts for log tables and triggers.
 
**What I changed / improved:**  
None.
 
**What I learned / decided:**  
A single `VARCHAR(60)` field cannot maintain history. Triggers are the cleanest way to capture every change automatically.
